# ADR-006: 글로벌 예외 핸들러 도입

## 날짜
2026-05-23

## 상태
`결정됨`

---

## 상황

`MemberController`, `OptionController`, `ProductController` 각각에 동일한 `@ExceptionHandler(IllegalArgumentException.class)` 메서드가 중복 선언되어 있다.
새로운 컨트롤러가 추가될 때마다 동일한 핸들러를 반복 작성해야 하며, 예외 응답 형식을 변경하려면 모든 컨트롤러를 수정해야 한다.

---

## 선택지

| 선택지 | 장점 | 단점 |
|--------|------|------|
| A. `@RestControllerAdvice` 글로벌 핸들러 | 예외 처리 한 곳 집중, 컨트롤러 핸들러 제거로 단순화, 응답 형식 일괄 변경 가능 | 어떤 예외가 어떻게 처리되는지 컨트롤러에서 직접 보이지 않음 |
| B. 현행 유지 (컨트롤러별 `@ExceptionHandler`) | 컨트롤러 단위로 예외 처리 파악 가능 | 중복 코드, 일관성 유지 어려움 |

---

## 결정

> **A를 선택한다.**

이유: 동일한 예외 처리 로직이 세 컨트롤러에 이미 중복되어 있고, 앞으로 컨트롤러가 늘어날수록 중복이 심해진다. `@RestControllerAdvice`로 한 곳에 모아 일관된 응답 형식을 보장한다.

---

## 트레이드오프

감수하는 것: 예외 처리 흐름이 컨트롤러 외부에 있어 추적 시 파일을 이동해야 함  
얻는 것: 중복 제거, 응답 형식 단일화, 컨트롤러가 HTTP 레이어에만 집중

---

## 결과

- `gift.infra.exception.GlobalExceptionHandler` (`@RestControllerAdvice`) 신규 생성
- `IllegalArgumentException` → 400 Bad Request 처리 일원화
- `MemberController`, `OptionController`, `ProductController`의 `@ExceptionHandler` 제거
